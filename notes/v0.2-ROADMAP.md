# v0.2 ROADMAP: RAG, Tools, and Architectural Hardening

## 1. Project Context: v0.1.0 Architecture
The Claude-Orchestrator v0.1.0 establishes a robust foundation for multi-agent coordination. It utilizes a sequential pipeline where specialized agents (Planner, Researcher, Writer, Evaluator) collaborate to satisfy complex user goals through a quality-controlled feedback loop.

### Core Pipeline Architecture:
- **PlannerAgent**: Decomposes goals into structured JSON steps.
- **ResearchAgent**: Generates analytical notes based on the plan.
- **WriterAgent**: Synthesizes context into a comprehensive draft.
- **EvaluatorAgent**: Performs JSON-based review and triggers repair loops.

---

## 2. v0.2 Strategic Objectives
The v0.2 release focuses on grounding agent knowledge in external data and providing the system with capabilities to interact with external tools.

### Key Pillars:
- **Retrieval-Augmented Generation (RAG)**: Move beyond static model knowledge for the Researcher.
- **Generic Tool Interface**: Provide a standard way for agents to execute actions (math, search, API calls).
- **Observability**: Implement structured logging and latency metrics.
- **Developer Experience**: Streaming support and standardized error handling.

---

## 3. Phased Implementation Plan

### Phase 0: Foundations & Observability
*Objective: Prepare the system for complex features by improving monitoring and error resilience.*
- **Structured Logging**: Implement standard Python logging to track `request_id` across all agent steps.
- **Latency Tracking**: Add metrics hooks to measure the execution time of individual agents.
- **Enhanced API Errors**: Standardize 4xx/5xx responses for model timeouts and parsing failures.
- **Files**: `src/config.py`, `src/orchestrator/core.py`, `src/api/main.py`.

### Phase 1: RAG & Tool Abstraction (Design)
*Objective: Define the architectural interfaces for external dependencies to ensure testability.*
- **Interface Definitions**:
    - `RAGClient`: Methods like `retrieve(query: str) -> List[Document]`.
    - `ToolRegistry`: A central registry for discovering and invoking Python functions.
- **Dependency Injection**: Update `ResearchAgent` to accept an optional `RAGClient`.
- **Files**: `src/tools/base.py`, `src/tools/rag.py`.

### Phase 2: Minimal RAG Implementation
*Objective: Implement a functional, testable RAG flow for local data.*
- **In-Memory Store**: A simple vector-like search for local documentation.
- **Research Query Logic**: Update the `ResearchAgent` to generate specific search queries based on `Planner` output.
- **Prompt Engineering**: Update system prompts to prioritize retrieved context over parametric knowledge.
- **Testing**: Implement `tests/test_rag.py` using mock document sets.

### Phase 3: Tooling & Streaming
*Objective: Enable interactive capabilities and real-time feedback.*
- **Initial Toolset**: Implement `web_fetch` (URL scraping) and `simple_math` tools.
- **Streaming Response**: Update the FastAPI endpoint to support `StreamingResponse` for step-by-step updates.
- **Agent Interactivity**: Integrate tool-calling logic into the Writer and Researcher agents.
- **Files**: `src/orchestrator/core.py`, `src/api/main.py`.

### Phase 4: Hardening & Release
*Objective: Ensure production readiness and documentation.*
- **Comprehensive Testing**: 100% coverage for new tool/RAG logic and failure modes.
- **Contributor Docs**: Update `CONTRIBUTING.md` with instructions for adding new tools.
- **v0.2.0 Release**: Finalize CHANGELOG and tag the release version.
